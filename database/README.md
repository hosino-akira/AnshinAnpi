# データベースの説明

利用者端末と管理画面は PostgreSQL を共用します。業務データは `public`、管理者アカウント、管理設定、マイグレーションの実行記録は `app_meta` に保存します。

## 業務テーブル

| テーブル | 用途 |
|---|---|
| users | 登録者の氏名、利用状態、登録日時 |
| face_templates | 暗号化した顔認証サービスの参照情報と認証資格 |
| recipients | 利用者ごとに最大 2 件の連絡先の氏名、メールアドレス、状態 |
| consents | 登録と送信への同意の版、日時、結果 |
| safety_checks | 登録通知、安否確認通知、連絡先変更通知の操作記録 |
| mail_deliveries | 宛先ごとの送信状態、失敗理由、再試行情報 |
| audit_logs | 管理操作と業務操作の署名付き監査記録 |
| terminals | 固定ロボットの設定と最終接続日時 |

`app_meta.administrator` は単一の管理者アカウント、`app_meta.admin_settings` は版管理された設定、`app_meta.schema_migrations` は実行済みのマイグレーションを保存します。

氏名、メールアドレス、顔認証サービスの参照情報は暗号化して保存します。元の写真は業務データベースに保存しません。管理者アカウント、連絡先、メールテンプレート、個人情報取扱文面の操作については [管理画面の説明](../backend/docs/ADMIN_API.md) を参照してください。

## 起動と初期化

ルートの `.env` に `POSTGRES_DB`、`POSTGRES_USER`、`POSTGRES_PASSWORD`、`POSTGRES_PORT` を設定します。既定のローカル接続先は `127.0.0.1:5433`、Compose 内部の接続先は `postgres:5432` です。

プロジェクトルートで実行します。

```powershell
docker compose up -d --wait postgres
.\scripts\database.ps1 -Action migrate
.\scripts\database.ps1 -Action status
```

`migrations` 内の SQL ファイルはすべて保持してください。初期化時に順番に実行し、実行済みの版はスキップします。新しいデータボリュームも Compose により自動でマイグレーションを実行します。

## 一時データと有効期限

一時的な写真、登録途中の情報、顔認証セッションは、単一のバックエンドプロセスの暗号化されたメモリだけに保存します。登録途中の情報と顔認証セッションの有効期限は最長 15 分です。関連する有効な API 呼び出しが連続 5 分間ない場合も失効します。端末内の画面操作はバックエンドのタイマーを更新しません。成功した要求の応答は 15 分間キャッシュします。

バックエンドの再起動により、未完了の一時操作は終了します。メール送信の ID は `safety_checks` 内で一意に保ち、同じ送信要求を再試行してもメールを重複作成しません。この実装は単一のバックエンドプロセスを使用し、複数インスタンスでの一時セッションの共有には対応していません。

## 文面とデータの保持

同意文面の初期値は [consent-policies.json](../backend/config/consent-policies.json) にあります。運用中の管理設定はデータベースに保存します。管理画面から個人情報取扱文面の新しい版と適用日を公開し、既存の同意履歴は上書きしません。

利用者を削除すると、業務上の氏名、メールアドレス、メールのスナップショットを直ちに消去します。顔認証サービスの参照情報はバックグラウンドのワーカーが削除します。30 日間の保持期間が終了し、外部データの削除が完了した後に利用者の行を物理削除するため、ワーカーを有効にしておく必要があります。

PostgreSQL のデータは Compose の名前付きボリュームに保存され、コンテナーを停止しても保持されます。バックアップとデータのエクスポートファイルは別途保存してください。
