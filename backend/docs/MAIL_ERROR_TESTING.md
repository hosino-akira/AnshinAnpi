# 邮件错误测试

管理端只显示式样书中的两种错误码和原文：

| 错误码 | 显示文字 |
|---|---|
| MAIL-001 | 確認メールを送信できませんでした。メールアドレスをご確認ください。 |
| MAIL-002 | ただいまメールを送信できません。時間をおいてお試しください。 |

SMTP 明确的恒久拒绝（如 550）以及退信显示 MAIL-001；其他发送故障显示 MAIL-002。数据库保留原始诊断代码，发送和重试逻辑保持不变。管理端状态栏继续显示「要確認」，不增加重发、关闭或删除按钮。

## 在真实管理页面检查显示

本地 PostgreSQL、后端（3002）和前端（5174）需正在运行。PowerShell 执行：

```powershell
cd C:\Users\27357\anshin-anpi\backend
npm run test:mail-display
```

打开 http://127.0.0.1:5174/admin，使用现有管理员账号登录，在首页点击「最新データを再読込」。

检查「メール送信エラー」列表中的两行，登録者为「メールエラー表示テスト」，分别显示 MAIL-001、MAIL-002 及上表原文，状态为「要確認」。其他数据不变时，「未解決」件数比测试前增加 2。重复执行命令会更新这两条测试记录，不会累加。

这个命令创建一个利用停止中的测试登録者、两个测试送信先和两个失败记录，使用 `example.invalid` 地址。它直接准备显示数据，不调用 SMTP、不发送邮件，不测试人脸或注册流程。测试时不要编辑或删除这个测试登録者，以便清理命令能验证归属。

完成后清理并再次点击「最新データを再読込」：

```powershell
npm run test:mail-display:clean
```

测试命令仅允许本机开发数据库及本地加密，拒绝生产环境和远程数据库。线上现有错误也会按上述两种错误码展示，线上不注入测试数据。

## 验证 SMTP 550 和 TIMEOUT 处理

```powershell
npm run test:mail-errors
```

自动测试使用模拟 SMTP 返回值，不修改 SMTP 设置，不发送真实邮件。覆盖 SMTP 550 的恒久失败、连接 TIMEOUT 的最多 3 次尝试、后台其他诊断原因向两种显示错误的转换，以及管理端 API 返回的错误码和文字。

仅输入不存在的邮箱不能稳定触发 MAIL-001：邮件服务器可能先受理，再产生退信。断开浏览器网络也不会制造 SMTP 错误，因为邮件由后端发送。先用显示测试确认页面，再用自动测试确认发送处理即可。
